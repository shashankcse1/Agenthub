# UI, API, and Product Design Coverage Map

## Scope
This document maps implemented backend APIs to current UI coverage and product design intent.
Canonical hierarchy and update rules are defined in `backend/docs/governance/documentation-source-of-truth.md`.
Detailed requirement-to-API-to-UI verification evidence is tracked in `backend/docs/governance/e2e-requirement-api-ui-verification.md`.

## Legend
- `Full`: UI supports primary operator workflow for the endpoint set.
- `Partial`: UI supports read-only or subset workflow.
- `Gap`: API exists but has no UI workflow yet.

## Frontend Component Architecture (Current)

Load order in `index.html` (before `app.js`):

1. `js/constants.js` — actor roles, API limits, view names, UI coverage keys
2. `js/api-cache.js` — boot-time GET dedupe
3. `js/api-client.js` — header construction and role normalization
4. `js/ui-coverage.js` — Gap endpoint gate and coverage render helpers
5. `js/platform-status.js` — operational banner polling
6. `js/operator-feedback.js` — feedback capture and analytics UI
7. `js/view-loader.js` — lazy view hydration (loads `overview` first; other views on first nav visit)
8. `js/ui-kit.js`, `js/view-search.js`, `js/table-search.js` — shared operator controls
9. `app.js` — workflow wiring and API orchestration

Performance posture: tab groups suppress init API storms; auto-refresh pauses when leaving a view; Overview hydrates only essential APIs at boot.

## Product Design Alignment Notes
- Startup-critical security and boot config remains environment-managed by design.
- Non-startup tunables are database-backed and configurable from UI.
- Agent ownership governance now has explicit UI workflows aligned with API controls and audit trails.
- Routing & Gateway leadership Packs 5–16 (GOV-AI-MARKET-005…016) plus Overview **Raise Leadership Score** (`POST /gateway/best-practices/leadership-bootstrap`) for configurable posture gaps.
- Routing & Gateway now includes database-backed system-level instruction controls and scoped system-rules classification (`global|user|team|group|owner|actor|agent`) applied at responses runtime.
- Providers now includes unified secret provider workflows with `db` (platform-encrypted), Vault, AWS, and Azure backends; db secret value storage (`PUT/GET/DELETE /secrets/providers/{id}/values*`) and gateway cursor secret binding (`GET/PUT/DELETE /gateway/cursor-secret-binding`) with masked readback and dual-approval-backed binding mutations.
- Routing & Gateway cursor token UI is deprecated; operators are directed to Providers. Legacy `/gateway/cursor-token` remains API-compatible with `Deprecation` headers and v3 binding migration on write.
- Routing & Gateway now includes a Cursor Gateway Integration hub plus tabbed OpenAI-compatible operator panels for all Cursor-backed families (Core, Media, Transport, Lifecycle), including previously API-only surfaces for `/v1/audio/*`, `/v1/messages`, `/v1/a2a/messages`, `/v1/images`, and `/v1/rerank`.
- Cursor Gateway Integration hub now includes session-aware automation recipes (curl/Python/TypeScript OpenAI-client) for secret-provider + gateway-binding setup, inference, and module metadata workflows; Overview includes a direct **Cursor Gateway** quick-start entry point.
- OpenAI-Compatible Gateway Ops model pickers and all `[data-gateway-model-select]` controls now load from the canonical platform register (`GET /providers/models/available`) with runtime policy keys `platform.ui_models.*`; Providers includes a **UI Model Availability Register** for operator verification. Cost calculator model browse remains pricing-catalog scoped.

Assistants / fine-tuning / passthrough operator notes (Routing & Gateway → Workspace):

- **Assistants API card:** create assistant (name/model/instructions/environment); table lists ID/name/model/env with row click → thread + delete forms; thread workflow (create thread, post message, list messages, **retrieve thread**, **retrieve run**, run thread with optional **Stream run (SSE)**); retrieve assistant + delete with prod dual-approval headers from table `environment`.
- **Fine-tuning Jobs card:** create job (model + training file ID from `/v1/files`); table with env column; retrieve job + cancel with prod dual-approval when job environment is prod.
- **Passthrough Proxy card:** provider/method/path/body + optional Headers JSON; prod requires Security Approver co-sign headers; responses in `#gatewayPassthroughPayload`.
- **Authz Explain** (Policies tab): preset actions `gateway.assistants.delete`, `gateway.fine_tuning.cancel`, `gateway.passthrough.execute` for pre-flight prod checks.
- Security console **Auth Explain** form: `POST /auth/authz/explain` with MFA verified toggle for auth-domain simulations.
- Playground **Run History → drill-down panel:** `GET /playground/runs/{run_id}/detail` tabs (run, feedback, assessment, audit, actions with assess/route-draft/observability pivot).
- Impact analysis and advanced-case register: `backend/docs/governance/litellm-assistants-parity-impact-analysis.md` (GOV-LITELLM-ASSISTANTS-001).
