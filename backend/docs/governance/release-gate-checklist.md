## B. Required Technical Gates

- [ ] Release evidence bundle generated and archived: `make release-evidence RELEASE_ID=<id> ENV=<staging|production> OWNER=<name>`
- [ ] Auto-ID option acceptable for non-production trace bundles: `make release-evidence-auto ENV=staging OWNER=<name>`
- [ ] Strict evidence gate used for production candidate: `make release-evidence-strict RELEASE_ID=<id> ENV=production OWNER=<name>`
- [ ] DATABASE_URL configured for migration validation (defaults to local `postgresql+psycopg://$USER@localhost:5432/agenthub` if unset).
- [ ] Full-stack review script passes: `bash scripts/full_stack_expert_review.sh --deep`
- [ ] Day-0 secrets validation passes: `cd backend && bash scripts/validate_day0_secrets.sh`
- [ ] Backend test suite passes.
- [ ] Frontend security smoke checks pass.
- [ ] One-command final gate runner passes: `bash scripts/run_final_gates.sh` (use `--quick` for focused backend validation during iterative reviews).
- [ ] Database migrations validated for target environment.
- [ ] Alembic version table compatibility verified (legacy PostgreSQL schemas with `alembic_version.version_num` length 32 are auto-expanded to 255).
- [ ] Control coverage checker passes.
- [ ] Feature/fix-level agent delivery checklist completed and attached (`backend/docs/governance/agent-delivery-checklist.md`).

## C. Security and Risk Gates

- [ ] No open critical vulnerabilities past SLA.
- [ ] High vulnerabilities have approved remediation or time-bounded exception.
- [ ] Residual risk register updated for accepted risks.
- [ ] Security risk closure tracker reviewed and updated: `backend/docs/governance/security-risk-closure-plan.md`.
- [ ] Token/secret handling changes reviewed.
- [ ] Production mutation guardrails reviewed.
- [ ] Password-login lockout runtime policy reviewed (`auth.login.max_failed_attempts`, `auth.login.lockout_minutes`).
- [ ] Unlock operation governance reviewed (`POST /auth/directory/users/{user_id}/unlock`, admin + MFA).
- [ ] Audit evidence verified for `auth.login.password` deny paths and `auth.directory.user.unlock` allow paths.
- [ ] Logging traceability verified for critical actions (actor_id, action_type, resource_type/resource_id, decision_outcome, trace_id).
- [ ] Evidence export/readback workflows validated for changed governance surfaces (for example gateway governance export or equivalent).

### C.1 Risk Closure Status Dashboard (Required)

Record current closure posture from `backend/docs/governance/security-risk-closure-plan.md` at release decision time.
Suggested command: `bash scripts/render_risk_closure_dashboard.sh`
Strict production recommendation: `bash scripts/render_risk_closure_dashboard.sh --strict-overdue`
Release evidence bundle capture: `metadata/risk_closure_dashboard.txt` (generated by `scripts/release_evidence_bundle.sh`).
Machine-readable snapshot: `metadata/risk_closure_dashboard.json`.
Decision record helper: `bash scripts/generate_release_decision_record.sh --release-id <id> --env <staging|production> --owner <name> --decision <TBD|GO|NO-GO> --accepted-risk <yes|no> --ciso-ack <yes|no>`.
Guardrail validator helper: `bash scripts/validate_release_risk_guardrails.sh --env <staging|production> --decision <TBD|GO|NO-GO> --decision-record <path>`.
Pending actions helper: `bash scripts/render_pending_closure_report.sh`.
Strict production release inputs (when `Decision=GO`): set `RELEASE_ACCEPTED_RISK_APPROVED=yes`, `RELEASE_CISO_ACK=yes`, and `RISK_EXCEPTION_REF=<approved-id>` when overdue items exist.

## E. Product and UX Gates

- [ ] Public error pages verified (404 and 500).
- [ ] Accessibility conformance report updated for current UI revision.
- [ ] Core user journeys validated for success and failure paths.
- [ ] Mobile and desktop sanity checks completed.
- [ ] UI export/report workflows validated for operator evidence usage where applicable.

### E.1 Discovery Dashboard Gate (when Discovery UI/API changes)

- [ ] Discovery posture metrics verified against source data (`healthy/stale sources`, `conflicts`, `high alerts`, `promote-ready`).
- [ ] Unified discovery triage filters validated (`type`, `urgency`, `search`) including empty-result handling.
- [ ] Discovery triage actions validated end-to-end:
	- approve/reject (`POST /discovery/resolve`)
	- promote (`POST /discovery/promote/{discovered_agent_id}`)
- [ ] Discovery source sync actions validated (`POST /discovery/sources/{source_id}/sync`) and downstream triage refresh confirmed.
- [ ] Role-boundary check confirmed: Agent Owner forbidden from global discovery inventory read (`GET /discovery/agents` deny path).
- [ ] Evidence commands captured for release notes:
	- `cd backend && python3 -m pytest tests/test_phase0_phase1.py -k "discovery_sync_and_list or discovery_conflicts_and_unmanaged_high_risk_alerts or pam_discovery_agent_owner_forbidden_from_global_inventory"`
	- `cd .. && node --check frontend/app.js`

### E.2 AI Skills Registry Gate (when Modules AI skills changes)

- [ ] AI Skills Registry endpoint validated (`GET /modules/skills`) including role-based read enforcement.
- [ ] Skill inventory filtering validated (`module_type in {ai_skill, skill}`) and non-skill modules excluded.
- [ ] AI skill registration governance validated (`module_type=ai_skill` requires security review ticket).
- [ ] Modules UI validations completed for AI Skills Registry load and module-type selection.
- [ ] Evidence commands captured for release notes:
	- `cd backend && python3 -m pytest tests/test_phase0_phase1.py -k "modules_register_ai_skill_requires_security_review_ticket or modules_skills_endpoint_returns_only_skill_types or modules_read_endpoints_enforce_read_roles"`
	- `cd .. && node --check frontend/app.js`

### E.3 Modules Integration Gate (when module integration metadata/sync changes)

- [ ] Module integration metadata fields validated in create/list/read paths (`integration_provider`, `integration_reference`, `integration_sync_status`, `integration_last_synced_at`).
- [ ] Integration provider validation verified (unsupported providers rejected fail-closed).
- [ ] Integration sync mutation validated (`POST /modules/{module_id}/integration/sync`) including role enforcement and no-provider guard.
- [ ] Modules UI validated for integration fields and Sync Integration action behavior.
- [ ] Evidence commands captured for release notes:
	- `cd backend && python3 -m pytest tests/test_phase0_phase1.py -k "modules_register_persists_integration_metadata_and_sync_updates_status or modules_integration_sync_requires_configured_provider or modules_read_endpoints_enforce_read_roles"`
	- `cd .. && node --check frontend/app.js`
