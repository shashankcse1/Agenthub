How Modules Fit Together

1. Register modules Publish module metadata, contract version, provenance, and optional integration provider references.
2. Validate agent pins Confirm agent module pins and config hashes before runtime promotion.
3. Plan upgrades Generate upgrade plans and sync integration-backed modules (for example Cursor skills).
4. Deprecate safely Retire modules with migration guidance, replacement IDs, and deprecation timelines.

Operator Guide by Area

Module Registry List and register secure modules with artifact signatures and required permissions. Use Use on a row to populate lifecycle forms. API: POST/GET /modules
Lifecycle Operations Load versions, validate agent pins, plan upgrades, and deprecate modules with audit-friendly guidance. API: /modules/{id}/versions, /agents/{id}/modules/*, /modules/{id}/deprecate
Integration Sync For integration-enabled modules, run Sync Integration after setting a valid reference (Cursor modules require cursor://workspace/...). API: POST /modules/{id}/integration/sync
AI Skills Registry Review skill-focused module inventory (ai_skill/skill) separately from the full catalog. API: GET /modules/skills
When should I register vs validate a module?

Register when publishing a new module artifact into the platform catalog. Validate when an agent already pins a module version and you need to confirm compatibility before rollout. Use upgrade planning when moving agents to a newer catalog version.
