How Playground Fits Together

0. Credentials Ensure model credentials exist in Providers (Store Secret Value or workload identity). Gateway Cursor runs need binding + gateway/cursor-token.
1. Compose and run Build a prompt with model candidates, optional voice or video attachments, and live stream preview.
2. Judge and retry Compare candidate model latency, cost, and quality scores; apply the winner or retry with the best result.
3. Govern prompts Save registry items, version changes, and promote approved prompts across environments.
4. Triage quality Review feedback, escalate low-quality runs, analyze rollups, and load test sets for regression checks.

Prompt Judge & Retry

        

          
          
          
          
          
        

      

      

        Compare every model in Candidate Models against the current prompt. Each candidate runs through gateway inference;
        results are ranked by quality score, then latency. Use Retry to re-run with the winning model.
      

      

        How judging works
        
    
          
  1. Run inference — POST /playground/compare calls gateway chat completion once per candidate model.
    2. 
          
  2. Measure — latency is wall-clock time; cost is estimated from token usage.
    3. 
          
  3. Score quality (0–1) — factual prompts (e.g. capitals) match against known answers; echo/stub responses score lowest; other prompts use a length heuristic.
    4. 
          
  4. Rank — highest quality wins; ties break on lower latency.
    5. 
          
  5. Retry — applies the winner to Selected Model and optionally appends judge guidance to the prompt before re-running.
