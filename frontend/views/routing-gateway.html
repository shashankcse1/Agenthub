Gateway Cursor Secret Binding

            

            
Cursor token configuration moved to Providers → Secret Providers. Use one secret provider for all secret storage (db, Vault, AWS, Azure), store secret values there, then bind the gateway below.

            
Workflow in Providers → Secret Providers: (1) Create a secret provider (db or external backend). (2) For db providers, store credentials via Store Secret Value (e.g. gateway/cursor-token). (3) Save Gateway Cursor Secret Binding. Legacy /gateway/cursor-token remains API-compatible but is deprecated.
